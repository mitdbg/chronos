Design comparison:

| Candidate | Correctness | Graph safety | Allocation cost | Decision |
|---|---|---|---|---|
| Initialization-time capacity | Covers all three buffers using worst-case virtual requests and padded chunk pages | Stable buffer identities; decode graph sizing remains based on `max_num_seqs` | Extra allocation only for chunked-local models; ordinary path unchanged | Selected |
| Guarded grow-on-demand | Covers observed overflow and avoids allocation on the common path | Unsafe after capture because replacing GPU buffers can leave graphs referencing old storage | Lowest initial allocation; three integer guards per build | Rejected |

The selected bound treats each scheduled token as a possible virtual request and sizes pages for each padded local-attention chunk. It preserves the existing allocation for models without `attention_chunk_size`.
