Diagnosis: the canonical startup and reconnect sequence is:

`CLIENT_HELLO → AUTH_OK → SERVER_READY`

A current-runtime client that waits for `SERVER_READY` before consuming `AUTH_OK`, activates streaming early, or incorrectly enters legacy fallback after receiving `AUTH_OK` can remain stuck in startup. The exact affected language/build still requires a sanitized control-frame capture.

Compatibility baselines are Python `0.12.0`, TypeScript `1.9.0`, and Go `0.8.3`. Older servers that genuinely omit `AUTH_OK` should trigger legacy fallback with one warning—not hang. Authentication retries must use jittered exponential backoff, one refresh per logical request, and single-flight refresh per token.
