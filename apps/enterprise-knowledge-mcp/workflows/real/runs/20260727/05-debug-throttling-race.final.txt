Investigation complete. The task branch remains intact, unmerged, and undeleted.

Diagnosis: shard reassignment copied an in-memory burst-credit pointer while policy hot-reload mutated its route/priority indices. The fast path validated the pointer by shard ID but not tenant ID, allowing a stale pointer to reference another tenant’s bucket. Misapplied credits then produced a 10–30 second above-quota allow window.

Evidence was strong:

- No failure occurred without policy reload.
- Over-allow reproduced consistently when reload overlapped reassignment.
- Stronger pointer validation eliminated the failure in staging.
