# Related Research Log

| Work | Source / Status | Relation to Chronos branching and difference |
| --- | --- | --- |
| [BranchBench / DB-Fork: Aligning Database Branching with Agentic Demands](https://arxiv.org/abs/2604.17180) | Anchor paper; Chronos benchmark reference | Defines the agentic branch-mutate-evaluate-prune workload space that Chronos targets, but evaluates branchable DBMSes rather than a bolt-on multi-store branch runtime. |
| [OrpheusDB: Bolt-on Versioning for Relational Databases](https://www.vldb.org/pvldb/vol10/p1130-huang.pdf) | Anchor paper; Chronos Orpheus-style backend reference | Provides the closest relational bolt-on versioning design, but focuses on dataset checkout and version retrieval rather than branch sessions, transactions, and merge validation for live applications. |
| [Generic Version Control](https://vldb.org/cidrdb/2025/generic-version-control-configurable-versioning-for-application-specific-requirements.html) | Anchor paper; Chronos branch-transaction framing | Unifies Git branches and MVCC transactions conceptually, while Chronos implements a practical bolt-on branch transaction layer over existing stores. |
| [Doltgres / Dolt](https://www.doltgres.com/docs/concepts/git/merge/) | Chronos benchmarked baseline; cited by BranchBench | Provides native Git-style branch, diff, commit, and merge over a content-addressed database, while Chronos keeps the underlying database native and adds branching above it. |
| [Neon](https://neon.com/docs/introduction/branching) | BranchBench evaluated system; explicitly requested | Provides storage-layer PostgreSQL copy-on-write branching through WAL/LSN lineage, while Chronos provides logical branch semantics without requiring Neon storage. |
| [Supabase Branching](https://supabase.com/docs/guides/deployment/branching) | Related hosted Postgres branching system; explicitly requested | Provides preview/deployment branches around Supabase projects, while Chronos targets runtime branch isolation, diff, and merge for agent state. |
| [Xata](https://xata.io/postgres-branching) | BranchBench evaluated system | Provides block-level copy-on-write PostgreSQL branching below an unmodified Postgres layer, while Chronos branches at the logical data and application-state layer. |
| [Tiger Data Fluid Storage](https://www.tigerdata.com/blog/fluid-storage-forkable-ephemeral-durable-infrastructure-age-of-agents) | BranchBench evaluated system | Provides block-layer forkable PostgreSQL infrastructure, while Chronos models branch lifecycle and merge semantics above storage. |
| [PostgreSQL transactions and savepoints](https://www.postgresql.org/docs/current/sql-savepoint.html) | BranchBench baseline | Gives fast temporary rollback, but lacks durable sibling branches, cross-branch comparison, and later merge. |
| [PostgreSQL template database clone](https://www.postgresql.org/docs/current/manage-ag-templatedbs.html) | BranchBench baseline | Provides coarse isolated database copies, while Chronos branches registered tables and can merge logical row changes. |
| [Decibel: The Relational Dataset Branching System](https://www.vldb.org/pvldb/vol9/p624-maddox.pdf) | Cited by OrpheusDB, BranchBench, and GenericVC | Implements relational dataset branching in a version-oriented storage engine, while Chronos is a bolt-on runtime that does not replace the database storage engine. |
| [DataHub: Collaborative Data Science and Dataset Version Management at Scale](https://www.cidrdb.org/cidr2015/Papers/CIDR15_Paper18.pdf) | Cited by OrpheusDB | Motivates collaborative dataset versioning, while Chronos applies related branch ideas to operational application state and agent workflows. |
| [Principles of Dataset Versioning](https://www.vldb.org/pvldb/vol8/p1346-bhattacherjee.pdf) | Cited by OrpheusDB | Studies recreation/storage trade-offs for dataset versions, while Chronos optimizes branch operations for mutable state stores and merge. |
| [Towards a Unified Query Language for Provenance and Versioning](https://arxiv.org/abs/1506.04815) | Cited by OrpheusDB | Addresses query-language support for provenance and versioning, while Chronos exposes branch operations as runtime APIs around existing SQL. |
| [Dat](https://dat-ecosystem.org/) | Cited by OrpheusDB | Supports dataset sharing and synchronization, while Chronos provides database-aware branch isolation and merge semantics. |
| [DBV](https://dbv.vizuina.com/) | Cited by OrpheusDB | Records SQL operations for replayable database versions, while Chronos stores branch-local state and computes diffs instead of replaying operation logs as the main abstraction. |
| [Liquibase](https://www.liquibase.com/) | Cited by OrpheusDB | Tracks schema evolution, while Chronos branches both schema-capable relational state and data changes. |
| [Git](https://git-scm.com/) and [Apache Subversion](https://subversion.apache.org/) for dataset versioning | Discussed by OrpheusDB and GenericVC | Provide the branch/diff/merge mental model, while Chronos adapts it to live database rows and workspace state. |
| [Temporal Data Management](https://www2.cs.arizona.edu/~rts/pubs/TKDEJan99.pdf) and [SQL:2011 temporal features](https://dl.acm.org/doi/10.1145/2380776.2380786) | Cited by OrpheusDB | Support linear time-travel over historical states, while Chronos supports divergent writable branches and merge. |
| [DB2 temporal data management](https://cs.ulb.ac.be/public/_media/teaching/infoh415/a_matter_of_time.pdf) | Cited by OrpheusDB | Provides time-travel features in a production DBMS, while Chronos needs non-linear branch histories for speculative work. |
| [Teradata temporal query processing](https://openproceedings.org/2013/conf/edbt/Al-KatebGCBCP13.pdf) | Cited by OrpheusDB | Supports temporal query processing, while Chronos focuses on branch isolation and merge rather than linear temporal analytics. |
| [Stratum approaches to temporal DBMS implementation](https://www.computer.org/csdl/proceedings-article/ideas/1998/83070004/12OmNzahccG) | Cited by OrpheusDB | Shows how temporal capabilities can be bolted onto existing databases, while Chronos bolts on branch creation, diff, and merge. |
| [BT-tree: A Branched and Temporal Access Method](https://www.vldb.org/conf/2000/P451.pdf) | Cited by OrpheusDB | Provides an index for branched temporal histories, while Chronos avoids requiring specialized temporal indexes in the underlying DBMS. |
| [Fully Persistent B+-trees](https://research.ibm.com/publications/fully-persistent-b-trees) | Cited by OrpheusDB | Provides persistent index structures for historical access, while Chronos uses ordinary tables plus branch metadata rather than persistent tree storage. |
